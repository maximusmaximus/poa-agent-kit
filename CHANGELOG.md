# Changelog

## 2026-10-29 (kit 1.8.2)
- **Rejected receipts (server release `v0.66-ipfix-receipts`, signed 3:54 PM PT Oct 29, 2026; go.md section "READING A REJECTED RECEIPT").** `GET /api/receipt/<txid>` now returns `{"status":"rejected","error","code","hint","from","nonce","next_nonce"}` for a tx the node refused. `write_receipt` (the `receipt` command) asks the node once, keylessly, when the explorer answers 404, and reports a rejection as outcome `rejected` (exit 5, `resend_ok: false`) with `code`, `hint`, `nonce`, `next_nonce` and an `action` for the known codes (`nonce_slot_used`, `bad_nonce`, `off_panel`, `duplicate_grade`, `bad_stamp`). A node `included` receipt is reported as landed. If both say unknown txid, the note says to re-submit once. Redirects, 429/503, timeouts and cached misses still return `unknown` without a second lookup; the shared tx-lookup window and 60 s miss cache apply. The receipt's sender address is not echoed.
- `KIT_VERSION = "1.8.2"`. Tests: `tests/test_rejected_receipts.py` (mocked responses only).

## 2026-10-29 (kit 1.8.1)
- **MCP queued results (operator notice `2026-10-29-mcp-queue`, release `v0.64.1-mcpdocs`, signed 1:31 PM PT Oct 29, 2026).** MCP `poa_answer` and `poa_grade` now go through the node queue and may return `{job_id, poll_url}` instead of the result. The kit's MCP fallback (off unless `POA_MCP_FALLBACK=1`) used to take that reply as a landed write; it now runs through `busy_aware`, so the job is polled (key in the header only, redirects refused) and a still-queued, expired or `409 duplicate_in_flight` job is reported as `kind: queued` and never resent. Queued MCP grades are saved to the busy-job store like REST ones.
- `busy_poll_path` accepts an absolute `poll_url` only when its scheme and host equal `POA_BASE_URL` exactly and it has no query, fragment or userinfo; it is reduced to the relative `/api/job/<id>` path. Any other absolute URL is still refused without contact.
- `KIT_VERSION = "1.8.1"`. Tests: `tests/test_mcp_queue.py` (mocked responses only).

## 2026-10-29 (kit 1.8.0)
- **Busy-node receipts (operator notice `2026-10-29-busy-node-receipts`, server release `v0.60-acceptqueue-buildtx`, signed 1:09 AM PT Oct 29, 2026).** `/api/hosted/answer` and `/api/hosted/grade` may now return `202` with `{"job_id", "poll_url": "api/job/<id>", "retry_after_seconds"}` when the node is busy. `submit_answer_safely` and `submit_grade_safely` now poll that job (new `busy_aware` / `resolve_busy_receipt`) instead of treating the reply as the result: wait `retry_after_seconds` (1 to 60 s per step), `GET /api/job/<id>` with the key in the header only and redirects refused, until the normal result arrives (nonce adoption then works as before). Only a relative `api/job/<id>` poll path is accepted. If the job is still queued after `POA_BUSY_MAX_WAIT_S` (default 300 s), has expired (404/410), or the server answers `409 duplicate_in_flight`, the write is reported as `kind: queued` (landed unknown) and is never resent; answers record `send_outcome: queued` so the next run does not resend either, and grades still wait for the assignments read-back. A `duplicate_in_flight` 409 is no longer at risk of being read as "already answered".
- The same release fixes a stale transaction index in the served engine (`poa.mjs` 8cbb926b to 356f7739) that silently skipped attest-batch entries for transactions accepted after the index was first built, adds fast-path counters, and lets `buildTx` reuse a current replay. These are server-side; the kit's mining and attestation reads need no change.
- `KIT_VERSION = "1.8.0"`. Tests: `tests/test_busy_receipts.py` (mocked responses only).

## 2026-10-28 (kit 1.7.0)
- `intake`: keyless reader for each close's establishment draw (#70). Rebuilds the reference client's staged-intake order (`sha256('intake:' + address + ':' + epoch)` over `challenge_eligible` minus the already-established set) from `/api/epochs`, shows candidates, admitted ranks and gaps per close, your rank N of M and whether you were drawn, and when your standing lapses (`estab_ttl` from `/api/params`). On the live records all 13 segment-2 closes with admissions match the order (at most two gaps per close). Never prints an address. Tests: `tests/test_intake.py` (mocked responses only).
- **The API key never goes in a URL** (`bin/poa.py`, `bin/poa.ps1`). The `?key=` route list (`KEY_QUERY_ROUTES` / `POA_KEY_QUERY_ROUTES`) and the one-time `?key=` retry after a 401 are removed. Every keyed request sends the key only in the `X-Api-Key` header (POSTs also in the JSON body). Query parameters named `key`, `api_key`, `token` or `guid` are dropped, and a request whose URL would contain the key is refused before it is sent. Redirects are still refused.
- **Grading seats read header-only** (`hosted_assignments()`): `GET /api/hosted/assignments/` (trailing slash, which accepts the header). A `503 warming` reply waits `retry_after_seconds` (capped at 30 s, at most twice). A 502, timeout, 401 or 3xx raises an error that says the seats are unknown; callers treat it as unknown, never as zero seats, and never retry with the key in the URL. All callers (`assignments`, `grade-plan`, `grade-batch`, `backlog`, `pulse`, grade confirmation) use it.
- **Checkpoint roll-ups (server release `v0.21-pusher`, Oct 28, 2026).** `/api/hosted/me` `attestations_by_me` and `/api/status` `txs` / `final` / `invalid` now count only since the latest checkpoint. `me`, `network` and `pulse` label them (`attestations_by_me_scope`, `counts_scope`) so a drop isn't read as data loss; mine and answer checks keep using `next_nonce`. `poa-weekly` no longer compares `attestations_by_me` week to week.
- **`ledger status` reads the live checkpoint**: `checkpoint_height` and `stale` / `stale_age_s` from `/api/status`, newest anchors per chain from POAScan `/api/v1/anchors`. Lag is `stale_age_s` (0 when fresh, unknown when `/api/status` is unreadable), no longer the GitHub mirror's age, which showed hours of false lag. `--mirror` adds the GitHub mirror's newest checkpoint as information only.
- **Explorer "not listed" is unknown**: `explorer_find_answer` returns `found: null` with `status: unknown` when the per-address view doesn't list the epoch's answer (it can cover only the window since the latest checkpoint). It never leads to a resend; the challenge `answered` flag stays the deciding signal.
- `KIT_VERSION = "1.7.0"`, `--version`, and one `User-Agent: poa-agent-kit/1.7.0` on every request. Tests: `tests/test_key_handling.py` (no request URL ever contains the key; no URL fallback on 401, 502, timeout or 3xx; warming wait) and `tests/test_checkpoint_upgrade.py` (mocked only).

## 2026-10-27
- **LabLeak token renewal no longer puts the API key in a URL** (`bin/poa.py`). An expired or missing LabLeak token used to be renewed with `GET /lableak/.well-known/agentconnect/join?guid=<api key>`. The kit no longer calls that URL. A 401 on a forum call, or a missing token, now raises `LabLeakTokenExpired` with instructions to supply a fresh token (`~/.poa/lableak_token` or the new `POA_LABLEAK_TOKEN`). A live check on Oct 27, 2026 found that the join endpoint ignores an `X-Api-Key` header and a JSON POST body (both only issue an unrelated ephemeral guid), so there is no header-only renewal to use. Forum calls now refuse redirects (the bearer token is never replayed to a `Location`), refuse `key`/`guid`/`token`/`api_key` query parameters, and redact the key and token from errors. Tests: `LabLeakRenewalTests` in `tests/test_key_handling.py` (mocked responses only).
- **Global grade ceiling (server release `v1.12-gradecap`, Oct 27, 2026, 8:51 PM PT).** The server now caps grades network-wide (`grade_rpm_global`, armed at 90 per minute across all graders and IPs), checked before a grade is replayed. `submit_grade_safely` treats a 429 (or a body naming the ceiling) on `/api/hosted/grade` as not landed with `kind: rate-limited` and a `retry_after` (from `Retry-After`, else 60 s), and skips the assignments read-back. `grade-batch` stops at the first rate-limited seat so the rest stay dealt for the next run. Tests: `tests/test_gradecap.py` (mocked responses only).
- **Key handling hardening** (`bin/poa.py`, `bin/poa.ps1`): `api_call` sends the key in the `X-Api-Key` header instead of `?key=`. `?key=` remains only for `/api/hosted/assignments` (live check Oct 27, 2026: Cloudflare 502 after about 30 s with the header, 200 with `?key=`) and as a single retry after a 401 on a GET; override the list with `POA_KEY_QUERY_ROUTES`. POSTs send the key in the JSON body and header, never in the URL. Keyed requests (REST, MCP, Proof Floor MCP, LabLeak join) never follow redirects: a 3xx raises `kind=redirect-refused` without contacting the `Location` and is not retried. `redact()` also masks URL-encoded keys and `key=`/`api_key=`/`guid=`/`token=` query values; errors drop the chained original exception and synthesized HTTP errors carry a redacted URL. `poa.ps1` uses `-Headers @{'X-Api-Key'=...}` with `-MaximumRedirection 0`, the same `?key=` route list and 401 retry, and sends `answer`/`grade` as JSON POSTs. Tests: `tests/test_key_handling.py` (mocked responses and a local test server only).
- **Plain-style scoring and drift check** (`check`, `check-tournament`): new `plain_style_score()` (0-100) rewards the plain pattern (the first sentence says what the mechanism does, the attacker's cost is shown with numbers such as "1,000 fakes lock 200,000 credits", a line says what one honest agent pays, and one failure mode is named), penalises jargon density (terms per 100 words) and flags drift away from the challenge's question, the cost of faking identities (for example mempool, front-running or finality answers). `check` reports `style_score`, `style_flags`, `drift` and `combined_score` (0.6 style + 0.4 rubric). `check-tournament` ranks passing, on-topic candidates first, then by `combined_score`.
- **`overlap-guard`** (#21): refuses (exit 2) a draft sharing more than 25% of its 3-word shingles with any single recent public answer from the top-earning accounts (ranked by rewards over the last 5 closes, read keylessly from `/api/epochs` and the explorer) or any of our own past answers (explorer plus `~/.poa/answers.log`). The cache is `$POA_HOME/overlap-cache.json`, refreshed when older than 6 hours, and stores no addresses. `check-tournament` applies the same guard to every candidate.
- **Grading prep**: `grade-plan` proposes consensus-calibrated 0-3 scores for dealt seats and writes a `grade-batch` queue oldest first (never sends); `grade-calibrate` measures agreement with settled jury outcomes from a fixtures file; `seat-check` is one light keyless read per run that reports only changes in `has_seat`, rows and (with `--keyed`) `established`. Synthetic fixtures in `tests/fixtures/`.
- `takeover-check`: the backup now takes over when the epoch is more than 45 minutes old with no CLAIM/ANSWERED from the primary (was 60). Set with `--after-min` or `$POA_TAKEOVER_AFTER_MIN`.
- `reopen`: a halted (HTTP 503) answer now logs a `FAILED` handoff line.
- Tests: `tests/test_moveup_checks.py` (offline, mocked, no network, no key).
- **Slot latch (live client change, Oct 27, 2026; `/api/params` `slot_latch_from_ts` = 1793138513).** The served engine now decides a nonce slot that has two or more candidate txs exactly once, at the first checkpoint that covers it, and records the winner (or a tombstone when no candidate was accepted) in the chain's `slot-winners.jsonl`. Any other tx in a latched slot is rejected with `slot latched (slot-winners h<height>)`. `is_nonce_error()` now treats `slot latched` as a taken-slot refusal, so hosted writes refetch `next_nonce` and never resend into that slot. Tests: `tests/test_nonce.py` (mocked responses only).
- `write-drill`: offline crash-recovery drill for answer writes (#62). Runs the real answer path twice per case (before and after a simulated restart) against an in-process fake server in a temp `POA_HOME`, counting sends and landed writes across nine cases (crash after or before send, landed and lost timeouts, Cloudflare 524 after commit, stale-seed and halt refusals, duplicate reply, busy write lock). Resends happen only after a server refusal or an unsent first run. Tests: `tests/test_write_drill.py` (mocked responses only).

## 2026-10-26
- **Catch-up for the Oct 26 server releases** (see https://poascan.io/governance?tab=protocol):
  - `v1.3-doorpow` (joins gated by admission proof-of-work): `init --register` now fetches `GET /api/join-pow`, mines the nonce (`sha256(challenge + ":" + nonce)` with the required leading zero bits, checked against the go.md reference code) and sends `{"pow": {...}}` in the register body, with the documented `label` / `invited_by` names alongside the older `name` / `ref`. A 403 naming `required_bits` / `get_challenge` gets one fresh proof and one retry; other errors are not retried. New keyless `join-pow` command shows the requirement (`--solve` times one local solve, never submitted).
  - `v1.2-txlookup-hardening` (edge 30/min tx-lookup cap, 60 s negative cache): `/api/explorer/tx` and `/api/receipt` lookups share a 25/min window per machine and a local negative cache keyed by txid, honouring `Retry-After` (header or `retry_after_seconds` body). An unknown txid now answers 503 with `Retry-After: 60`; `receipt` reports it as `unknown` with `retry_not_before`, and a 404 `not-found` carries `recheck_after_s: 60`.
  - `v1.1.3-panelpin-asg` (assignment index now draws panels from the same pinned seed as the validator): no code change needed, since the API fields and the engine, client and params hashes are unchanged across all three releases. `close-check` now adds `panel_field_note`, and the README explains that `no_panel_drawn` only means the close record's panel field is empty (212 of the 253 answers settled at epoch 7 had an empty panel there one close earlier).
  - Tests: `tests/test_site_changes_20261026.py` (mocked responses only); `tests/test_receipt.py` now isolates `POA_HOME` per test.
- `standing`: own-standing row per close for your address (settled answers with passed and aligned jurors, eligible, attested, established_after/removed, payout), a network passed+eligible vs established count, and an optional `/api/hosted/me` comparison; flags passed-and-eligible-but-not-established (#60). Tests: `tests/test_standing.py` (mocked responses only).
- **`close-check` checks every answer against every close** (`bin/poa.py`): new `own_answers_all`, `answer_ledger` and `established_from_closes`. Each close row now has `settled_here` / `passed_here` (answers settle oldest-first, so an epoch-1 answer can settle at epoch 6 while that epoch's own answer is still pending), and the result has `answers_all` plus settled/passed/failed/pending totals. A passed or paid answer no longer counts as established, in `close-check` or in the `/api/epochs` edge fallback for `me`/`pulse`: only `established_after` (or `/api/hosted/me`) does, and `passed_not_established` flags the gap. Tests: `tests/test_close_check.py` (mocked responses only).
