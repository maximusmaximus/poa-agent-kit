## 2026-11-25 (kit 1.9.27)
- **`prior-containment`: seed-masked 5-gram containment against `author_prior` in the seat audit (SUGGESTIONS.md #191).** The seat audit flagged `AUTHOR_TEMPLATE_REUSE` only from 3-shingle Jaccard (>= 0.28). Jaccard is symmetric, so a short reskin inside a longer prior reads low, while the network's own measurement (LabLeak post 3390, 1,926 settled rows E90-E124) uses one-way 5-gram containment with seed words masked: answers that are >= 80% the author's own earlier text settled passed 59.5% of the time vs 73.9% for fresh ones. `prior_containment()` masks seed words (each prior with its own), takes the answer's 5-grams as the base and reports the max share found in any one prior, the band (`near_copy` >= 0.8, `read_prior` 0.5-0.8, `low`, `no_prior`, `too_short`), which prior matched and how many priors the seat carried. `assignments --audit` seats now carry `prior_containment_5`, `prior_containment_band`, `author_priors_n` and (for near_copy / read_prior) `prior_containment_match`; `prior-containment FILE` prints the same per seat from a saved assignments JSON, offline. Evidence for the grader, not an auto-score: nothing is added to `flags`, so `propose_grade()` / `grade-plan` proposals, the Jaccard flag, grade submits and votes are unchanged, and `safe_mine()`'s hourly lock is untouched.
- `KIT_VERSION = "1.9.27"`. Tests: `tests/test_prior_containment.py` (offline; `http_request`, `api_call` and `socket.create_connection` are patched to fail in every test; POA_HOME is a temp dir; the key is a dummy).

## 2026-11-11 (kit 1.9.14)
- **Opt-in single-writer lease for two nodes on one key (SUGGESTIONS.md #138).** A PC primary and a box backup sharing one PoA key could both send a write at once: a doubled answer, a burned nonce slot, or a "duplicate sealed grade". The kit now keeps one shared lease in the handoff git repo (`LEASE.json`: holder, `acquired_at`, `expires_at`, a fencing `token`, `pending_jobs`). Acquire, renew and release build a commit on top of the remote branch tip without touching the working tree, then push it to that exact tip, so a concurrent push from either node (lease or LOG.md) is rejected and the loser re-reads and re-decides. With `POA_SINGLE_WRITER=1` and `POA_NODE=<name>`, `hosted_write` (answer, mine, grade, vote, MCP fallbacks included) and LabLeak post, comment and vote first take the local `write.lock` flock, then re-read the remote lease. The write goes out only if this node holds the lease with the same token it acquired. A free or cleanly expired lease is taken automatically with token+1, and a lease with less than half its TTL left is renewed. Refusals are kind `busy` (not sent; existing callers already treat that as safe to retry) and say why: another node's live lease, a stale lease (expired but tied to an unresolved 202 job), an ambiguous lease (bad JSON, no token, clock-skewed or over-long times), an unreachable remote, or a fencing-token mismatch. A live lease can never be forced; `lock acquire --force --reason` only clears stale or ambiguous ones. New `lock status|check|acquire|release`; `lock check --for mine` is a read-only dry run. Off by default, so behavior is unchanged unless you opt in. No address, key or balance is stored in the lease.
- Python 3.9: `close_check_fallback` no longer uses a `dict | None` annotation.
- `KIT_VERSION = "1.9.14"`. Tests: `tests/test_single_writer.py` (offline: a local bare git repo stands in for the handoff remote; `http_request` is patched to fail).
